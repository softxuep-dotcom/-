# Autonomous Game Development Rules

- Work autonomously until the release checklist passes.
- Do not ask about routine design or implementation decisions.
- Record material assumptions in docs/DECISIONS.md.
- Never stop after implementation: run, playtest, review, fix, and retest.
- Do not claim completion without launching the production build.
- Preserve working user changes and commit only intentional project changes.
- UI must be responsive and usable with mouse, keyboard, touch, and tablet input.
- Do not ship placeholders, debug UI, console errors, broken controls, or inaccessible screens.
- Prefer a polished small game over a broad unfinished game.
- Ask only for credentials, irreversible external actions, or genuine blockers.
