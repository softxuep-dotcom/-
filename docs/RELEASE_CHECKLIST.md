# Browser Game Release Checklist

适用产品：轻量低多边形 3D 布娃娃物理喜剧  
首发平台：CrazyGames  
次要兼容：Poki  
目标方向：手机竖屏 9:16 优先、平板竖屏与桌面居中竖屏容器、单指触控优先、短局重玩

## 使用规则

- `[REQUIRED]`：发布候选版本必须通过。
- `[RECOMMENDED]`：应完成；未完成必须在 `docs/QA_REPORT.md` 解释影响。
- `[OWNER]`：仅由项目所有者在平台后台完成。Codex不得执行、不得代勾，也不得将其作为本地完成阻塞。
- `N/A`：只能用于确实不适用的条目，必须在条目后写明理由。
- 不得仅凭“代码看起来正确”勾选条目。每个通过项必须能在 `docs/QA_REPORT.md` 找到测试、截图、测量或构建证据。
- 任何回归都需要重新验证受影响条目。
- 最终不得存在 P0 或 P1 问题。
- Codex完成标准是所有本地 `[REQUIRED]` 项通过并生成可上传包；`[OWNER]` 项由用户上传后单独验收。

缺陷等级：

- **P0**：崩溃、无法开始或完成核心流程、无限加载、严重丢档。
- **P1**：核心输入、物理、UI、平台SDK或主要设备上存在严重错误。
- **P2**：明显降低品质、理解度或留存，但仍可完整游玩。
- **P3**：不影响核心体验的轻微润色问题。

## 1. 产品与范围

- [x] `[REQUIRED]` `docs/GAME_DESIGN.md` 已定义玩家幻想、核心动词、核心循环、失败、奖励、重开和进度。
- [x] `[REQUIRED]` 前三关代表最终体验，而不是与后续版本脱节的临时教程。
- [x] `[REQUIRED]` 正式内容不少于 12 个经过设计的关卡。
- [x] `[REQUIRED]` 至少存在 4 类会改变玩家决策的物理机关或交互元素。
- [x] `[REQUIRED]` 每 2～3 关至少出现一种新机制、新目标或新组合。
- [x] `[REQUIRED]` 游戏具有明确的结束、阶段目标或持续追求，不会在内容耗尽后无反馈地继续。
- [x] `[REQUIRED]` 游戏名称、美术、角色、关卡和文案具有原创性，不是对参考游戏的直接复制。
- [x] `[REQUIRED]` 内容适合 13 岁以上主流网页游戏平台用户。
- [x] `[RECOMMENDED]` 一次自然游戏会话可以持续 5～15 分钟。

## 2. 首次进入与新手体验

- [x] `[REQUIRED]` 从页面可用到进入可操作游戏状态不超过一次主动点击。
- [x] `[REQUIRED]` 玩家在首次操作前能通过画面或短提示理解当前目标。
- [x] `[REQUIRED]` 教学优先使用情境提示和操作反馈，不使用大段文字墙。
- [x] `[REQUIRED]` 首次提示会在玩家掌握操作后消失，且不会长期遮挡场景。
- [x] `[REQUIRED]` 第一次成功发生得足够早，并提供明显的视觉和声音反馈。
- [x] `[REQUIRED]` 第一次失败能快速重开，不强制回到主菜单。
- [x] `[REQUIRED]` 所有不可交互的开场、动画或演示均可跳过。
- [x] `[RECOMMENDED]` 第一分钟内至少出现一次能体现布娃娃喜剧特色的记忆点。

## 3. 核心循环与游戏性

- [x] `[REQUIRED]` 玩家能在约 10 秒内说清“我要做什么”和“怎样算成功”。
- [x] `[REQUIRED]` 每局包含至少一个有意义的时机、方向、位置、风险或资源选择。
- [x] `[REQUIRED]` 输入后立即产生可感知反馈；不存在明显“按了但像没按”的状态。
- [x] `[REQUIRED]` 成功与失败由可理解的规则决定，不依赖不可读的随机结果。
- [x] `[REQUIRED]` 失败原因可从画面、提示或回放结果中理解。
- [x] `[REQUIRED]` 重开时间短，不存在重复的长加载、长动画或多层确认。
- [x] `[REQUIRED]` 连续试玩 10 分钟后，核心循环仍有目标变化或技术提升空间。
- [x] `[REQUIRED]` 不存在一种无需观察或思考即可稳定通关绝大多数关卡的无脑策略。
- [x] `[REQUIRED]` 奖励、评分或解锁系统强化核心玩法，而不是用无意义数值拖延流程。
- [x] `[RECOMMENDED]` 至少一种结果具有“差一点”或“再试一次会更好”的重玩动力。

## 4. 布娃娃物理与手感

- [x] `[REQUIRED]` 物理使用固定时间步；在 60、120、144 或 165 Hz 显示刷新率下玩法结果保持一致。
- [x] `[REQUIRED]` 布娃娃关节不会频繁爆炸、无限抖动、穿透或卡进场景。
- [x] `[REQUIRED]` 关键交互使用简化且对齐的碰撞代理。
- [x] `[REQUIRED]` 角色质量、阻尼、关节限制和冲量经过调校，既有喜剧效果又可理解。
- [x] `[REQUIRED]` 高速物体不会稳定穿过关键碰撞体；必要时启用连续碰撞或子步进。
- [x] `[REQUIRED]` 摄像机能持续展示关键动作，不会被墙体遮挡或因冲击剧烈晃动到无法判断。
- [x] `[REQUIRED]` 镜头震动、慢动作和粒子只强化重要瞬间，不妨碍操作和目标判断。
- [x] `[REQUIRED]` 物理休眠和对象回收正常，不会因大量静止刚体持续消耗性能。
- [x] `[REQUIRED]` 角色掉出世界、卡死或长时间静止时存在可靠的恢复/失败处理。
- [x] `[RECOMMENDED]` 关键碰撞具有力度分级的音效、粒子、形变或相机反馈。

## 5. 关卡与难度曲线

- [x] `[REQUIRED]` 每一关均可从全新存档正常开始、完成、失败并重开。
- [x] `[REQUIRED]` 所有关卡至少完成一次人工或自动辅助的完整通关验证。
- [x] `[REQUIRED]` 前三关分别完成：操作介绍、目标强化、第一次机制组合。
- [x] `[REQUIRED]` 难度增长来自机制组合和决策要求，而不只是提高数值或减少容错。
- [x] `[REQUIRED]` 新机关首次出现时有安全、清晰的展示空间。
- [x] `[REQUIRED]` 不存在出生即失败、无预警伤害、不可见碰撞或无法恢复的软锁。
- [x] `[REQUIRED]` 各关卡的视觉地标、布局或目标足以区分，不是简单复制。
- [x] `[REQUIRED]` 关卡评分标准可理解，并与玩家实际表现一致。
- [x] `[RECOMMENDED]` 至少有 2 个关卡允许不同但都合理的解法。

## 6. UI、HUD 与视觉层级

- [x] `[REQUIRED]` UI具有与游戏主题一致的字体、色板、材质语言和动效，不像通用后台或默认组件库。
- [x] `[REQUIRED]` 正常游戏时中心及下方主要操作区保持清晰。
- [x] `[REQUIRED]` 手机竖屏持续HUD覆盖面积原则上不超过游戏视口的 25%。
- [x] `[REQUIRED]` 桌面端保持居中的竖屏游戏区域，并使用主题化背景安全填充两侧，不把画面横向拉伸。
- [x] `[REQUIRED]` 目标、分数、剩余次数等最高优先级信息一眼可读。
- [x] `[REQUIRED]` 菜单、弹窗和设置打开时，场景输入与摄像机控制正确暂停或隔离。
- [x] `[REQUIRED]` 所有按钮具有默认、悬停/按下、禁用和键盘焦点状态。
- [x] `[REQUIRED]` 胜利、失败、暂停、设置、奖励和解锁界面具有清晰的主要操作。
- [x] `[REQUIRED]` 文本在 `devicePixelRatio: 1` 和非全屏嵌入尺寸下仍清晰可读。
- [x] `[REQUIRED]` UI在长文本、不同语言和数字位数增加时不会溢出。
- [x] `[REQUIRED]` 没有占位文字、Lorem ipsum、测试按钮、空白面板或开发者文案。
- [x] `[RECOMMENDED]` 非必要动效尊重 `prefers-reduced-motion`。

## 7. 输入、响应式与浏览器行为

- [x] `[REQUIRED]` 核心玩法可使用鼠标完成。
- [x] `[REQUIRED]` 全部核心玩法可使用单手、单指触控完成，不依赖多点触控或设备姿态。
- [x] `[REQUIRED]` 鼠标完整映射同一套核心动作，不形成另一套不同规则的玩法。
- [x] `[REQUIRED]` 键盘相关玩法具有清晰映射；ESC 或空格可按产品设计暂停/恢复。
- [x] `[REQUIRED]` 输入统一映射为游戏动作，菜单与游戏场景不会同时响应同一次输入。
- [x] `[REQUIRED]` 松开鼠标、触控取消、窗口失焦或弹出菜单后不会留下“按键卡住”状态。
- [x] `[REQUIRED]` 游戏不会让方向键、空格、滚轮或触控拖动导致父页面意外滚动。
- [x] `[REQUIRED]` 窗口缩放、浏览器地址栏收起/展开、全屏切换和横竖屏变化后画面、UI和输入坐标仍正确。
- [x] `[REQUIRED]` 手机刘海和安全区域不会遮挡关键按钮。
- [x] `[REQUIRED]` 布局使用动态视口高度和安全区，不因 `100vh` 与移动浏览器工具栏差异产生裁切。
- [x] `[REQUIRED]` 高频触控目标原则上不小于 44×44 CSS px，且相邻按钮间距足以避免误触。
- [x] `[REQUIRED]` 高频操作位于单手拇指易达区域，不依赖 hover、右键或精细像素级拖拽。
- [x] `[REQUIRED]` 横屏手机显示安全降级布局或旋转提示，不发生崩溃、关键UI丢失或进度重置。
- [x] `[REQUIRED]` 触控按钮尺寸和间距足够，不容易误触相邻功能。
- [x] `[REQUIRED]` 失去页面焦点或切换后台时游戏自动暂停或安全停止模拟。
- [x] `[REQUIRED]` 恢复焦点时不会出现时间步爆炸、角色飞出或音频重复播放。

- [x] `[REQUIRED]` 所有第三方素材、字体和音频具有可发布许可，并记录来源。

## 11. 性能与加载预算

- [x] `[REQUIRED]` 首次进入有真实进度或明确的加载反馈，不会让玩家误以为页面冻结。
- [x] `[REQUIRED]` 首次可玩内容优先加载，其余内容按需或后台加载。
- [x] `[REQUIRED]` CrazyGames首包不超过 20 MB，以满足移动首页资格目标。
- [x] `[REQUIRED]` CrazyGames总包不超过 250 MB，文件数不超过 1500。
- [x] `[REQUIRED]` 使用外部加载资源时，在标准测试环境达到可玩状态不超过 20 秒。
- [x] `[RECOMMENDED]` 为兼容 Poki，初始下载进一步控制在 8 MB以内。
- [x] `[REQUIRED]` 中端移动设备最低保持 30 FPS，目标稳定 60 FPS。
- [x] `[REQUIRED]` 手机竖屏是性能调优的第一基准；像素比、阴影、后处理和粒子可根据设备能力降级。
- [x] `[REQUIRED]` Chrome/Edge桌面端正常玩法中无持续严重卡顿。
- [x] `[REQUIRED]` 在 4 GB RAM Chromebook 等级设备上不发生崩溃或不可接受的卡顿；无实体设备时记录仿真方法和验证缺口。
- [x] `[REQUIRED]` 性能测试覆盖：首次加载、最高物理活动、最多粒子、最大UI和关卡切换。
- [x] `[REQUIRED]` 后处理、阴影、灯光和粒子均有明确预算；低性能设备可以降级。
- [x] `[REQUIRED]` 性能结论来自实际浏览器测量，而不是仅凭代码估计。
